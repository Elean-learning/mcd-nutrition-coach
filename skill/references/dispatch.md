# 场景路由与拒答

## 一、正例触发句

| 用户说法 | 路由到 | 说明 |
|---|---|---|
| 巨无霸多少卡路里 | 能力 1 + 2 | 单品营养解析与占比 |
| 巨无霸加中薯条加中杯可乐，一共多少热量 | 能力 1 + 2 | 多品求和 |
| 这餐钠超标了吗 | 能力 2 | 参考摄入量对比 |
| 我在减脂，麦当劳该怎么点 | 能力 3 | 约束求解，需要热量上限与蛋白质下限 |
| 帮我配一份 700 卡以内、蛋白质 35 克以上的套餐 | 能力 3 | 显式约束求解 |
| 控糖的话哪个饮料能喝 | 能力 1 + 2 | 偏糖指标解析 |
| 我今天还剩 500 卡额度，能吃什么 | 能力 1 + 2 | 传入 remaining 做额度评估 |
| 这单用完券要多少钱 | 能力 4 | 券后算价 |
| 本月有什么活动 | 能力 5 | 活动日历 |
| 就照这个帮我下单 | 能力 6 | 先摘要，再显式确认 |

## 二、负例与拒答路由

| 用户说法 | 处理方式 |
|---|---|
| 肯德基全家桶多少卡 | 说明本技能只覆盖麦当劳餐品，不做跨品牌估算 |
| 红烧肉热量多少 | 超出范围，说明仅覆盖麦当劳餐品 |
| 优惠券的使用规则条文是什么 | 属纯客服事务，引导至麦当劳官方渠道 |
| 附近哪家店还开着 | 属门店查询事务，引导用户用官方渠道，或改用 MCP 的门店工具查询 |
| 我有糖尿病，能吃巨无霸吗 | 明确不接诊，建议咨询医师或注册营养师，可只提供营养数据供其参考 |
| 帮我吃一周只吃麦当劳减肥 | 不输出极端饮食方案，说明本技能不做个体化营养处方 |
| 帮我刷 1000 单 | 拒绝，说明不支持任何违规或异常操作 |
| 直接帮我付钱 | 说明支付环节需用户本人完成 |

## 三、边界用例处理

### 用例 1：餐品名称口语化或含错别字

先把名称归一为麦当劳标准餐品名再查询。若归一后仍无法确定是哪一个餐品，向用户确认，不要猜。

### 用例 2：工具未收录该餐品

直接说明该餐品没有返回数据，请用户确认名称或换一个餐品。禁止套用相近餐品的数值。

### 用例 3：用户提供自己的数值

例如用户说"我这杯按 145 千卡算"。以用户数值为准，通过 `--override` 或 `--items` 传入，来源标记为 override 或 explicit，并在答复中注明该数值来自用户。

### 用例 4：糖数据缺失

麦当劳营养接口通常不直接给糖。不要把碳水当作糖，也不要填 0。保持缺失并告知用户该项无数据。

### 用例 5：约束互相冲突导致无解

例如要求热量低于 300 千卡同时蛋白质高于 40 克。脚本会返回无解，此时向用户说明冲突点并给出放宽建议，不要返回凑合方案。

### 用例 6：用户要求下单但未确认

先输出订单摘要并询问是否确认。用户未明确表示确认前，不调用下单工具。

### 用例 7：金额与脚本参考值不一致

以 `calculate-price` 返回为准。脚本中的金额不含券，仅用于组合筛选，需要在答复中说清口径差异。
